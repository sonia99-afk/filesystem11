# Почему отдельная таблица single_user_projects

В проекте уже была начата многопользовательская архитектура: users, workspaces,
workspace_members, роли и workspace API.

По текущей задаче это пока не нужно. Нужен один общий логин и хранение проектов
на сервере.

Чтобы не удалять уже сделанную работу и не ломать существующие таблицы, текущий
backend использует `single_user_projects`.

Этот backend не содержит:

- регистрации;
- приглашений;
- участников;
- ролей;
- workspace API;
- разграничения доступа между пользователями.

Позже данные из `single_user_projects` можно перенести в будущую многопользовательскую
схему.
